# Обновление: «живые» камео в свободном режиме (AI Совёнок / ES-AI-Mod)

## Что было раньше
- Другой персонаж заходил **только** в романтический момент или изредка «проходил мимо» (5%).
- Заходил, говорил **ровно одну фразу** и тут же уходил — выглядело заскриптованно.
- Реплика камео не знала контекста разговора (ему не передавали ни историю, ни память).
- Локации с одним персонажем казались пустыми.

## Что стало
1. **Случайные персонажи, случайное количество.** За одну реплику может зайти 1 персонаж,
   иногда двое (пары «по канону» вроде Алиса+Ульяна заходят вместе чаще). Максимум — 2
   одновременно (настраивается `cameo_max_extra`).
2. **Реплики «в тему» и без контекста.** Каждая репlika камео с вероятностью `cameo_ctx`%
   строится по **контексту последних реплик** (хвост из 6 сообщений сцены) плюс
   **память** (сжатая история разговоров Семёна с активной героиней из `memory/conversations`).
   Остальные — нейтральные по ситуации (поприветствовать, спросить, пошутить).
3. **Частота под контролем.** Базовый шанс появления за обмен — `cameo_freq`% (дефолт 25).
   В романтический момент шансы выше и тоже масштабируются частотой (при 25% — как раньше:
   хозяин 55%, романтичная локация 22%, прочее 12%). Кулдаун 5 реплик после появления — как был.
4. **Остаются в сцене и продолжают говорить.** Если включено `cameo_stay` (дефолт вкл),
   зашедший **не уходит после первой фразы**: он остаётся на экране (спрайт не пропадает,
   эмоция лица меняется от реплики к реплике), и за каждый обмен с шансом `cameo_interject`%
   рандомно вклинивается новой фразой. Перед уходом говорит случайное число фраз 1..`cameo_stay_lines`.
5. **При входе в локацию кто-то может уже быть на месте** — с половинным шансом от частоты,
   чтобы локации не казались пустыми, когда гуляешь с одним персонажем.
6. **Смена локации / персонажа / выход из чата** — остающиеся камео уходят вместе со сценой.

## Где настраивать
**Окно настроек (вкладка «Промпты»)**, под тумблером «Появления в локациях»:
- «Остаются в scene и говорят» — тумблер `cameo_stay`
- «Частота появлений» — слайдер 0–100% (`cameo_freq`)
- «Фраз до ухода» — слайдер 1–4 (`cameo_stay_lines`)
- «Шанс реплики в разговоре» — слайдер 0–100% (`cameo_interject`)
- «Реплики в тему (по контексту)» — слайдер 0–100% (`cameo_ctx`)

**В игре** (экран «Настройки AI», раздел «Сцена»): тумблер «Остаются в сцене…” и кнопка
«Частота появлений: N%» — нажимать по кругу (0-5-10-15-20-25-35-50-70-100).

Все правки пишутся в `config.json` сразу и применяются «на лету» (мод читает их каждый ход).

## Новые ключи config.json (дефолты)
```json
"cameo_freq": 25,        // базовый шанс появления за обмен, %
"cameo_stay": true,      // зашедшие остаются и продолжают говорить
"cameo_stay_lines": 2,   // доп. фраз перед уходом (случайно 1..N)
"cameo_interject": 35,   // шанс реплики остающегося камео за обмен, %
"cameo_ctx": 70,         // доля реплик «в тему» (по контексту), %
"cameo_max_extra": 2     // макс. заходящих одновременно
```

## Что поменялось в коде
| Файл | Изменение |
| --- | --- |
| `mod/es_ai_cameo.rpy` | Новая логика: настройки из конфига, случайное количество, «остаются в сцене» (`ES_AI_CAMEO_ACTIVE`), `es_ai_cameo_tick` (вклинивания), `es_ai_cameo_on_arrive` (хук входа в локацию), контекст (`ES_AI_RECENT_LINES`), эмоции у реплик, фолбэки |
| `mod/es_ai_locations.rpy` | `es_ai_girl_enter` **сохраняет** камео в сцене (раньше стирал при каждой реплике героини); `es_ai_set_location` чистит камео и зовёт хук «уже на месте»; `es_ai_girls_reset` сбрасывает состояние |
| `mod/es_ai_screens.rpy` | В экране настроек: тумблер «Остаются в сцене», кнопка частоты по кругу |
| `server/main.py` | `/cameo`: режимы `enter`/`here`/`stay`, контекст + память (summary) + `others` в промпте, `reply_rules` (в т.ч. защита для Ульяны); `get_config_state` отдаёт новые ключи |
| `server/settings_window.py` | Вкладка «Промпты»: 2 тумблера + 4 слайдера, save_all/reset_all |
| `server/config.json` | Новые ключи с дефолтами |

## Безопасность / совместимость
- Старый вызов `/cameo` (без новых полей) работает как раньше.
- При выключенном `cameo_stay` поведение полностью как раньше (зашли — одна фраза — ушли).
- Если сервер недоступен — фолбэк-реплики из встроенных таблиц (как раньше) + общий набор для режима «остался».
- После обновления **перезапусти игру** (мод поднимет сервер с новым `main.py`).

## Проверено
- Синтаксис всех файлов (py_compile + извлечение python-блоков .rpy).
- Юнит-тесты серверного `/cameo` (все режимы, контекст, память, защита для несовершеннолетней, фолбэк при падении LLM).
- Симуляция клиентской логики: математика шансов, кулдаун, случайное количество (1–2),
  регистрация «остающихся», tick (реплика → счётчик → уход), on_arrive, цикл частоты,
  обратная совместимость stay=False, cover-нардяд в романтике.
- Сходимость вероятностей: on_arrive 49% при freq=100, 16% при freq=25, 0% при freq=0;
  появление после реплики 22.5% при freq=25.
